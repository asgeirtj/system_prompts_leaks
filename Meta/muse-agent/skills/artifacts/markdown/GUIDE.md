# Markdown documents

- A Markdown deliverable is plain text written directly with the file tools. There is no compile step: the `.md` file at the root of the project directory is the deliverable.

- Read the shared [Markdown guide](/opt/muse/assets/artifacts/references/markdown.md) for headings, lists, tables and links, and the shared [prose guide](/opt/muse/assets/artifacts/references/prose.md) for what the words say.

## Write for the reader

- Identify the document's purpose, its audience and the decision or understanding it should support. Outline the argument or sequence before expanding it.

- Lead with the main point, use concrete language and choose headings that describe the content. Support factual claims with sources and keep findings apart from recommendations.

- Let the structure follow the content: real headings, real list syntax, and tables only where rows and columns genuinely align.

- The file ships as the user's own text. Leave out build scaffolding, HTML the user did not ask for, and trailing commentary that is not part of the document.

## Read it back

- Read the finished file in full before returning the link. Check that the structure renders as intended, links and code examples work, and no placeholder or scratch content remains.

- Remove repeated conclusions, filler and headings that add no information. Keep the user's requested terms and scope.
